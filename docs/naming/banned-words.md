# Banned Words

## 목적
- 의미가 흐리거나 너무 범용적이라 유지보수 비용을 높이는 단어를 지양한다.
- 아래 단어를 반드시 금지한다는 뜻이 아니라, 사용 시 근거가 필요하다는 뜻이다.

## 지양 단어
| Word | Why | Preferred direction |
| --- | --- | --- |
| `data` | 어떤 데이터인지 드러나지 않는다 | 구체 대상 명시 |
| `info` | 정보의 종류와 용도가 모호하다 | `summary`, `profile`, `details` 등 구체화 |
| `util` | 책임이 뭉개지기 쉽다 | 역할 중심 클래스명 |
| `manager` | 관리 대상과 행위가 불명확하다 | `Service`, `Registry`, `Factory` 등 구체화 |
| `temp` | 임시 상태가 영구 코드로 남기 쉽다 | 실제 의미로 변경 |
| `misc` | 분류 포기 신호다 | 도메인별 재분류 |
| `handler` | 예외 처리 외 문맥에서 너무 광범위하다 | 실제 역할로 명시 |
| `common` | 공통이라는 사실 외엔 설명이 없다 | 공통 대상과 기능 명시 |
| `dto` | 타입 분류만 있고 의미가 없다 | `*Request`, `*Response`, `*Command` 등 |

## 예외 처리
- 이미 외부 라이브러리/프레임워크 관례로 고정된 이름은 허용할 수 있다.
- 예외가 필요하면 `decision-log.md`에 사유를 기록한다.
